## 产品介绍

MayDolist 是我为 Windows 开发工作流开发的本地优先工具。编码、Review 和日常事务经常交错发生：临时想法需要马上记下，PR 和 Issue 需要持续跟进，便签又散落在不同窗口里。我希望把这些内容放到一个随时能叫出来、平时安静待在托盘中的入口。

使用时，可以通过全局快捷键快速记录 Todo 或创建便签，再到「今日焦点」查看待处理事项。GitHub 条目可以转成保留来源的待办，便签可以独立悬浮在桌面上。应用将记录、判断下一步、执行与回到来源连在一起，减少在工具之间重新寻找上下文的过程。

## 我负责的内容

### 从使用场景确定产品结构

我设计并实现了快速收集、收件箱与今日焦点，让临时记录先有落点，再进入具体清单。逐条处理模式提供今天做、稍后做、转列表、完成和删除等动作，帮助使用者把收件箱转化为下一步行动。

### 完成桌面交互与本地数据链路

我使用 Vue 和 TypeScript 构建界面，由 Tauri 与 Rust 承担窗口、托盘、快捷键和本地存储。围绕便签自动保存、悬浮窗口及跨窗口刷新处理交互细节；同时提供备份、导出、导入预览与恢复能力，让数据能够被检查和带走。

### 把 GitHub 上下文接进待办

我实现了 PR / Issue 的行动信号展示、转待办与来源关联，并进一步补齐状态同步：来源关闭或 PR 合并后，默认自动完成关联待办；来源重新打开时保留本地决定，网络失败也不会误完成任务。应用通过 GitHub CLI 读取信息，不在应用内保存 GitHub token。

### 持续处理发布后的体验问题

我维护构建和版本发布，逐步修复便签空状态、标题编辑、主题及窗口操作问题。功能是否容易使用、误操作能否恢复，与新增功能本身一起成为迭代内容。

## 最终成果

截至 2026 年 9 月 14 日，MayDolist 已公开发布 v1.3.8。待办、悬浮便签、GitHub 跟进和本地备份已整合为可安装的 Windows 桌面应用。

其中，GitHub 来源同步让待办不再只保存一个静态链接：远端事项结束后，本地能够跟随更新，同时保留用户的手动选择。这是我从个人工作中的小问题出发，持续完成产品设计、实现与发布的一次实践。
